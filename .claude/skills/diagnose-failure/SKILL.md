# 障害診断手順

## 1. 一次分類(log-triage / haiku)

生ログを主任へ持ち込まない。log-triage に以下を依頼:

- 失敗の件数と原因グループ分け
- 代表エラー1件ずつの抜粋(ファイル:行)
- 環境起因(パス・依存・PATH)か、コード起因かの推定

## 2. 再現確認

- 失敗テストを単体で再実行: `uv run pytest <path>::<test> -x -v`
- 決定性を確認(2回実行して同じ失敗か)。不安定なら並行性・時刻・乱数を疑う

## 3. 原因特定してから修正

- 症状への対症療法(sleep追加・skip・リトライ増加)を先にしない
- 仮説 → 検証コマンド → 結果 の順で記録する
- 同一の失敗を過去に診断していないか DECISIONS.md / TASKS.md を確認

## 4. 環境起因の典型(この環境)

- `python` はMS Storeスタブ → 必ず `uv run` 経由で実行
- ffmpeg/ffprobe のPATH未反映 → 設定のパス解決を使う
- 日本語ユーザー名パス → エンコーディング指定(UTF-8)漏れを疑う
- Docker未起動 → integration テストは PG/Redis 必須。eager/SQLite で代替可能か確認

## 5. 記録

再発しうる診断結果は DECISIONS.md へ1〜3行で記録する。
