# 変更レビュー手順

## 1. レビュー種別の選択

| 変更内容 | レビュアー |
|---|---|
| 通常のコード変更 | sonnet(通常レビュー) |
| 認証・トークン・subprocess・外部入力・公開ゲート | security-reviewer(opus・読取専用) |
| データモデル・状態遷移・冪等性・複数モジュール横断 | architect(opus) |

## 2. レビュー範囲の指定

`git diff --stat` で変更ファイルを列挙し、レビュアーには変更ファイルと関連テストのみ渡す。

## 3. 観点

- 受入条件を満たすか(仕様の該当セクション番号を明記して確認)
- CLAUDE.md の絶対原則違反がないか
- テストが実際に検証しているか(アサーションの実質性)
- 冪等性: 2回実行で重複・二重計上しないか
- fail-closed: エラー時に公開・課金側へ倒れないか

## 4. 指摘の扱い

- BLOCKER/HIGH: 修正するまで Phase を完了にしない
- MEDIUM以下: TASKS.md の未解決事項に記録して先へ進んでよい
- 指摘には必ず ファイル:行 と修正案を含めさせる

## 5. 再レビュー

修正後は指摘箇所のみ再確認。全体再レビューはしない。
