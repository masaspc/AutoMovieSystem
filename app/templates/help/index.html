使い方ガイド

初めての方は、上から順に読みながら実際に画面を操作してみてください。 まずはFakeモードで流れを確認し、立ち絵掛け合い動画は準備ができてから有効にします。

① 立ち絵動画の準備 ② 全体の流れ ③ 動画を1本作る ④ 色の意味 ⑤ たくさん作る ⑥ YouTube接続 ⑦ 困ったとき ⑧ 用語集

① 立ち絵掛け合い動画を作る準備

ずんだもんと四国めたんが会話する動画には、公式立ち絵、VOICEVOX Engine、設定の反映が必要です。 ここは最初の一度だけ行います。設定前でも、Fakeモードの通常動画フローは試せます。

先に素材の利用条件を確認してください。 公式立ち絵はリポジトリに同梱していません。収益化、法人利用、利用地域を含む条件を確認したうえで、 正規に入手した透明PNGだけを配置します。 公式イラスト素材ページ とキャラクター利用ガイドラインを読んでください。
1

公式立ち絵を配置する

プロジェクト直下の assets/characters に、キャラクターごとのフォルダーを作ります。 normal.png は必須です。talk.png を用意すると、発話中に簡易口パクします。 

assets/characters/
  zundamon/normal.png
  zundamon/talk.png       # 任意: 発話中の差分
  metan/normal.png
  metan/talk.png          # 任意: 発話中の差分
  tsumugi/normal.png      # つむぎを選ぶ場合は必須
2

VOICEVOXと立ち絵レンダリングを有効にする

.env を開き、以下を設定します。春日部つむぎを出さない場合は、 最終行を DIALOGUE_CAST=zundamon,metan にします。 

COMPOSE_PROFILES=voicevox
TTS_PROVIDER=voicevox
DIALOGUE_SCRIPT_ENABLED=true
CHARACTER_RENDER_ENABLED=true
DIALOGUE_CAST=zundamon,metan,tsumugi

ずんだもん・四国めたんは基本の2人です。つむぎは設定に含めた場合だけ、補足が有効な場面で台本の候補になります。

3

Dockerを再作成し、設定を確認する

プロジェクトのフォルダーでPowerShellを開き、次を実行します。初回はVOICEVOXのDockerイメージ取得に時間がかかります。 

.\scripts\dev.ps1 up

起動後に「設定」を開き、TTS_PROVIDER が voicevox、 DIALOGUE_SCRIPT_ENABLED と CHARACTER_RENDER_ENABLED が True、話者設定が意図どおりであることを確認します。

設定ページを開く
4

最初の1本は最後までプレビューする

次の「動画を1本作る」の手順でレンダリングまで進めます。動画プロジェクト詳細で、立ち絵、話者、字幕、音声、 クレジットが期待どおりか確認してから承認してください。素材が不足している場合は、背景だけの動画にせずレンダリングを停止します。

VOICEVOXを使った投稿では、使用した話者のクレジットを概要欄へ自動で追加します。立ち絵の利用条件と音声の利用条件は別なので、両方を確認してください。

③ はじめの一歩: 動画を1本作ってみる

実際に手を動かして、①〜⑤を順番に試してみましょう。

1

{{ icon('idea', 18) }} 企画(ネタ)を選ぶ

「企画」ページを開くと、ネタの一覧が並んでいます。 気になるタイトルをクリックして詳細画面を開き、「スコア計算」ボタンを押してください。 需要・独自性など6項目で点数がつきます。

企画ページを開く
2

{{ icon('script', 18) }} 台本を作る

同じ企画詳細画面で「台本生成」ボタンを押すと、AIが動画の構成とナレーション原稿を 数秒で自動作成します。続けて「動画プロジェクト作成」ボタンを押すと、 動画を組み立てるための箱ができます。

  • 台本生成
  • 動画プロジェクト作成
3

{{ icon('film', 18) }} 動画を組み立てる

「動画プロジェクト」の詳細画面を開くと、 右上に青い「▶ 次の作業」ボタンが出ます。押すたびに次の順で進みます (1〜2分かかる作業もあります)。レンダリングが終わると、実際に再生できる動画が 画面に表示されます。

  • 素材準備
  • 音声合成
  • レンダリング
  • 自動レビュー
レビューで問題(Blocking Findings)が見つかった場合は赤字で表示され、 その先(承認・投稿)には進めません。内容を見直してください。
4

{{ icon('check', 18) }} 内容を確認して承認する

自動レビューに合格したら、同じ画面の「承認」ボタンを押します。 承認した人はログイン中のユーザー名として記録されます(監査ログ)。 気になる点があれば「却下」を選んでやり直せます。

5

{{ icon('upload', 18) }} 投稿する

承認後に出てくる「▶ アップロード」ボタンを押します。 Fakeモードでは実際のYouTubeには繋がらず、テスト用の動画ID(fake-xxxxx)が 発行されます。実際のYouTubeに繋ぐ方法は ⑤ YouTube接続で説明します。

⑤ たくさん作りたいとき(グロース機能)

1本ずつ手作業するのが大変になったら、「成長」「ベンチマーク」ページを使います。 登録者数1000人を目指すための機能です。

1

{{ icon('target', 18) }} 伸びている動画を登録する

「ベンチマーク」ページで、伸びている他チャンネルの動画URLを 登録します。中身をコピーするのではなく、「タイトルの付け方」「構成」など 成功パターンだけを参考にした、自分用の新しい企画をAIが作ってくれます。

ベンチマークページを開く
2

{{ icon('layers', 18) }} 量産バッチでまとめて制作

「成長」ページの「量産バッチ実行」で本数を指定すると、 スコアの高い企画から自動レビューまでまとめて作られます。 ここでも投稿は自動化されません — 合格した動画は 「動画プロジェクト」ページで1本ずつ確認・承認してください。

成長ページを開く
3

{{ icon('chart', 18) }} 結果を見て、勝ちパターンを繰り返す

投稿後、統計が反映されると「成長」ページに登録者数への進捗と、動画ごとの 「登録効率」が表示されます。効率の良い動画は「続編を企画化」ボタンで すぐに次の企画にできます。

⑥ 実際のYouTubeに接続する方法

ここまでの操作はすべて「Fakeモード」(テスト用のダミー投稿)でした。 実際のYouTubeチャンネルに投稿したい場合は、以下の準備が必要です。

この作業はブラウザだけではできません。 サーバー(このアプリを動かしているPC)のターミナルで、コマンドを1つ実行する必要があります。 作業自体は一度きりで、以降はブラウザだけで投稿できるようになります。
1

Googleでアプリを登録する

Google Cloud Console でプロジェクトを作成し、「YouTube Data API v3」を有効化します。 「OAuth同意画面」でアプリ名などを入力し、投稿に使うGoogleアカウントを 「テストユーザー」として追加してください。

2

認証情報(鍵)を作る

「認証情報を作成」→「OAuthクライアントID」→種類はデスクトップアプリを選びます。 作成後にダウンロードできる client_secret_xxxx.json というファイルが、 アプリを認証するための鍵になります。

このファイルは絶対にリポジトリへコミットしないでください (.gitignore 済みの安全な場所に保存)。
3

.env ファイルに設定を書く

サーバーの .env ファイルに、以下を追記します。

SECRET_ENCRYPTION_KEY=<十分に長いランダム文字列>
YOUTUBE_PROVIDER=real
YOUTUBE_OAUTH_CLIENT_ID=<client_secret.jsonのclient_id>
YOUTUBE_OAUTH_CLIENT_SECRET=<client_secret.jsonのclient_secret>
4

サーバーで認証コマンドを実行する

サーバーのターミナルで次を実行すると、ブラウザが開いてGoogleアカウントの許可を求められます。許可すると自動的に完了します(コピー&ペースト不要)。

uv run python scripts/youtube_oauth_setup.py --client-secret path/to/client_secret_xxxx.json

取得した認証情報は暗号化してデータベースに保存されます。パスワードのような 平文の情報が画面やログに表示されることはありません。

5

設定できたか確認する

「設定」ページを開き、YOUTUBE_PROVIDER が real、YOUTUBE_OAUTH_CLIENT_ID・ YOUTUBE_OAUTH_CLIENT_SECRET が「設定済み」になっていれば準備完了です。

設定ページを開く
接続後も安全設計は変わりません。 最初の投稿は必ず「非公開(private)」になります。実際に世界に公開されるのは、 自動レビュー合格・人間の承認・重複チェックなど6つの条件をすべて満たし、 かつ設定で AUTO_PUBLISH_ENABLED=true(既定は無効)にした場合だけです。

⑦ よくある詰まりどころ

項目をクリックすると答えが開きます。

「実行中です」と表示されてボタンが進まない
同じ処理が裏側でまだ動いている最中です(二重に実行しない安全のための仕組みです)。 数十秒待ってからページを再読み込みしてください。
「公開予約」を押すと拒否理由が表示される
故障ではありません。既定では自動公開が無効になっているため、わざと拒否されています。 投稿ページから理由を確認できます(承認が未完了、自動公開が無効、など)。
ボタンを押すとエラーになる
左メニューの「ジョブ」を開くと、失敗した処理の一覧と 「再実行」ボタンがあります。エラー内容もそこで確認できます。
画面が真っ白になった/古い表示のまま動かない
ブラウザの「戻る」ボタンで古いキャッシュ画面が表示されることがあります。 ページを再読み込み(F5)してから操作し直してください。
ログイン画面でパスワードがわからない
このアプリを起動した人に、サーバーの .env ファイルにある ADMIN_USERNAME / ADMIN_PASSWORD を確認してもらってください。
立ち絵動画のレンダリングが失敗した
assets/characters の normal.png を確認してください。 DIALOGUE_CAST に tsumugi を含めた場合は、 tsumugi/normal.png も必要です。次に「ジョブ」でエラー内容を確認し、 素材または設定を直してから「再実行」を押します。
声がFakeのまま / VOICEVOXの声が出ない
.env の TTS_PROVIDER=voicevox と COMPOSE_PROFILES=voicevox を確認し、.\scripts\dev.ps1 up で再作成してください。 「設定」ページで値を確認できます。Docker Desktopが起動していない場合も音声生成はできません。
