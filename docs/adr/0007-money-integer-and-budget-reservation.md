# ADR-0007: 金額は整数マイクロ単位 + 予算のアトミック予約

Status: Accepted (2026-07-04) — 主任(Fable 5)承認済み

## Context
コスト制御は UsageRecord.estimated_cost の合算で日次/月次予算を判定する。二つの穴がある:
1. **浮動小数ドリフト**: ADR-0002 は SQLite 互換のため Numeric/Decimal を避ける方針。
   estimated_cost を float で持つと多数レコード合算で丸め誤差が蓄積し、閾値(80%/100%)判定が
   ぶれる。SQLite に Decimal native が無いことが根因。
2. **check-then-act の競合**: 予算判定 → 呼び出し → 事後 UsageRecord 記録、の順のため、
   複数 Celery ワーカーが同時に 95% を読んで各自実行し予算を超過し得る(予約が無い)。
   さらに (呼び出し成功) と (UsageRecord commit) の間でクラッシュすると実費が発生済みでも
   未記録となり、予算を**過少計上**して制御をすり抜ける。

## Decision
- 金額は **整数マイクロ単位(micro-USD 等、`*_micros` 命名)** で保持し、SQLite/PG 双方で
  厳密一致・丸め無しにする。表示時のみ換算。
- 予算ゲートは **事前予約(reserve)** 方式:呼び出し前に見積コストで残予算をアトミックに
  減算(行ロック or 予約テーブル UPSERT)し、成功時に実コストで確定、失敗時に解放する。
  これで同時実行の超過と過少計上の双方を塞ぐ。
- 予約枯渇(100%到達)時は AI ジョブを BUDGET_HELD へ(ADR-0006)。非 AI 処理は無条件継続。
- LLM キャッシュヒット時は予約・課金を行わない。

## Consequences
- 予算制御が並行環境・クラッシュ時も単調で決定的になり、E2E の UsageRecord 検証と整合。
- 予約/解放のトランザクション設計が増える。eager モードでは自明に直列化され回帰を検出しやすい。
