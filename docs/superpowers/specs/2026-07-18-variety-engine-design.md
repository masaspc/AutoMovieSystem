# 演出バリエーションエンジン 設計スペック

日付: 2026-07-18
状態: ユーザー承認済み(ブレインストーミング経由)

## 背景と目的

実運用で「動画が単調になりやすい」ことが判明した。原因は毎回同じ話の流れ・同じ演出
(導入→解説→まとめの固定リズム、固定カメラワーク、エンディング3パターン)にある。

他YouTuber研究の結果を反映する:

- 視聴維持率の実証則: **2〜3分ごとの「パターン転換」**(話題転換・テロップ・カット切替)が
  単調さ離脱を防ぐ。冒頭30秒の結論/問いかけ提示、セクション間の「ブリッジ(引き)」が有効
- 2026年のYouTubeアルゴリズムはコメント・保存の質を維持率と同等以上に評価する
  → 視聴者への問いかけによるコメント誘発が重要
- ずんだもん系人気動画の共通要素: クイズ・「〇〇3選」形式・ストーリー性・ツッコミの個性

**目的**: 動画ごとに構成・演出が決定論的に変化し、視聴者を飽きさせない。
同一動画の再レンダリングは同一結果(冪等性の絶対原則を維持)。

## 決定事項(要件確定済み)

- 変化対象: **台本構成・掛け合いリズム / 映像演出 / OP・EDバリエーション** の3領域
  (音声・音響演出は今回スコープ外)
- 乱数は `video_project_id`(台本生成時は `topic_id`)シードの sha256 決定論抽選。
  既存のBGM選曲・サムネ配色・アウトロ抽選と同じパターン
- 抽選結果は `Script.source_manifest` に記録し、将来セルフレビューで
  「どの演出が維持率に効いたか」の相関分析に使えるようにする

## コンポーネント設計

### 1. 台本バリエーション: `app/services/scripts/variety.py`(新規)

```python
@dataclass(frozen=True)
class VarietyPlan:
    hook_style: str        # 導入フック型
    corners: list[str]     # 挿入コーナー(1〜2種)
    tsukkomi_density: str  # high | medium | low
    bridge_style: str      # セクション間ブリッジ型
```

カタログ(定数辞書。名称+プロンプト指示文のペア):

- **導入フック5型**: 衝撃数字型 / 問いかけ型 / 失敗談型 / 結論先出し型 / あるある型
- **コーナー6種**: クイズ / 雑学(トリビア) / あるある / 視聴者Q&A風 /
  「〇〇3選」リスト化 / たとえ話チャレンジ
- **ツッコミ密度3段階**: high(全セクションでボケツッコミ) / medium / low(要所のみ)
- **ブリッジ型**: 次セクション予告の言い回しバリエーション

主要関数:

- `pick_variety_plan(seed: str, *, template: str) -> VarietyPlan`
  - sha256決定論抽選。同一seed+templateで常に同一結果
  - 構成テンプレート別の適合フィルタ: news_commentary にクイズは入れない、
    shorts はコーナー0〜1個に制限、など
- `variety_prompt_block(plan: VarietyPlan) -> str`
  - 台本プロンプトへ注入する「今回の演出指示」ブロックを生成

### 2. generator.py 統合

- `generate_script` 内で `pick_variety_plan(seed=topic_id, template=...)` を呼び、
  プロンプトへ注入。`PROMPT_VERSION` を bump(冪等キーが変わり旧キャッシュ無効化)
- 全動画共通の必須指示を追加:
  - 2〜3分ごとに話のパターンを転換する(コーナー挿入・視点切替・テンポ変化)
  - 視聴者への問いかけを1箇所以上入れる(コメント誘発。例:「あなたはどっち派?」)
- `VarietyPlan` の内容(dict化)を `Script.source_manifest["variety_plan"]` に保存

### 3. 映像演出バリエーション

同じシード体系(`video_project_id`)で以下を抽選し、レンダリング時に適用:

- Ken Burns カメラワーク方向(ズームイン/アウト×パン方向で4種)
- セクション切替の xfade トランジション種(fade / wipeleft / slideup / circleopen 等4〜5種)
- 見出しテロップの登場スタイル(数種)
- アクセント配色シフト(シリーズブランディングの色相を軸に小幅変化)

`RENDER_SPEC_VERSION` を bump(旧レンダリングキャッシュ無効化)。
抽選ロジックは `app/services/media/` 配下に置き、renderer/visuals から参照する。

### 4. OP/ED拡充

- エンディング掛け合い(`app/services/scripts/outro.py` `_OUTRO_VARIATIONS`):
  現行3 → **8バリエーション**に拡充(チャンネル登録+グッドボタン懇願の主旨は全変種で維持)
- オープニングは導入フック5型が実質OPバリエーションとして機能
  (コールドオープン=結論先出し型 等)。独立したOP画面は作らない(YAGNI)

## エラー処理

- カタログ・抽選は純粋関数で外部依存なし。失敗モードは事実上ない
- 未知のtemplate名は適合フィルタなし(全カタログ対象)で動作する(fail-soft)

## テスト計画

- 抽選の決定論性: 同一seed→同一 `VarietyPlan`、異なるseed→分布が偏らない(数種のseedで確認)
- テンプレート適合フィルタ: news_commentary にクイズが入らない、shorts のコーナー数制限
- `variety_prompt_block` が全カタログ組合せで空にならない
- generator統合: プロンプトに演出指示ブロックが含まれる、source_manifestに記録される
- 既存パイプライン回帰(unit全件+実FFmpeg media/e2e)

## スコープ外

- 音声・音響演出のバリエーション(感情振れ幅・話速・SE頻度) — 将来検討
- チャンネル別の演出プロファイル(カタログはまず全チャンネル共通)
- 演出×維持率の相関分析の実装(source_manifest記録までが今回。分析はセルフレビュー側の将来拡張)
